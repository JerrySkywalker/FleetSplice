- Genuine `@getpaseo/plugin@0.12.0` imports and original ProviderRegistration /
  PluginServerContribution compile with strict types. Independent lock closure
  restores on Node 24.20.0 / SQLite 3.53.4; final pilot TypeScript is 5.9.3.
- Published official PluginRuntime, its compiler/worker and real registration
  context load the original provider in an isolated in-process sandbox. Catalog,
  list/open, mock completion, close/reconnect and refresh run. Grade:
  **REAL_SDK_LOADED_SANDBOX**. App-session wire and native transport are synthetic;
  this is not a normal daemon installation or real Codex qualification.
- **18 assertion groups pass**, recording **36 route cases** including known
  blockers. B2: 11 pass / 6 blocked / 1 not_run; C: 9 pass / 7 blocked / 2 not_run.
  Real Windows security/TUI/Writer and complete history are not claimed passed.
- Existing FS classes are unmodified. Both routes refuse injected configuration,

  hold uncertain delivery and reject/disable unsafe targetless controls.

## What prevents full parity

C fails modern daemon.pid discovery, still uses resume for loaded attach, and
turns a completed no-caller-echo submission into ambiguity. C has the existing
exact-target/fence control seam; B2's public prompt/interrupt input lacks the
expected native target, so the pilot disables unsafe controls. Its native
discovery/Windows proof is not implemented.

Both have a demonstrated fresh-connection/bare-adapter retry gap after uncertain
delivery, and neither proves native event cursor recovery. C's outer Hub durable
admission was not exercised, so do not generalize the bare-adapter replay finding
to every integrated FS path. Native security/TUI return, phone topology, full
durable history and matched performance remain unqualified.

# R01 — Paseo v0.11.2 as an unmodified replacement

## Input scope and verdict

Examined 2026-10-15: released `v0.11.2@75953250959979b8f088bbca8dbd6ee61d0151b1`, current source `0708b8295c102d1d5ea5acbfa512691c7d0e19ba`, official Codex source `6fbd7be1518d259e30e6fef48f05f433d2461a20`, local `codex-cli 0.162.1`, and the pinned FS candidate/receipts in [the source register](SOURCE-REGISTER.md). Relevant Paseo implementation files were unchanged between release and HEAD. This is a source assessment; no Paseo binary, phone, remote relay, real transcript, or Owner environment was tested.

**A = hard fail against the unchanged P0-NATIVE oracle and source-level fail for P0-HISTORY bounded residency.** Paseo's useful managed workflows are real alternatives if the Owner expressly changes the workflow; they do not make an externally launched live TUI part of its managed Agent. Codex itself can support a shared daemon in some launch classes, but Paseo's released adapter does not attach to that daemon.

## Native identity boundary

Process PID, app-server PID, Native Thread ID and Paseo Agent ID are four distinct identities. Official Codex [can auto-start/reuse a shared daemon](https://github.com/openai/codex/blob/6fbd7be1518d259e30e6fef48f05f433d2461a20/codex-rs/tui/src/startup_orchestration.rs#L520) for eligible ordinary launches, but it can also select embedded mode or fail to detach on Windows. HAPI's [`hapi codex` shared sessions](https://github.com/tiann/hapi/blob/5847b034e5cb84f2617766945c994b7905c5c03e/docs/guide/codex-shared-sessions.md) establish a startup-managed near-equivalent, not proof of unwrapped late discovery. Paseo import can preserve a Native Thread ID while changing the app-server and Writer; that fails the original live-TUI oracle.

Paseo is a strong managed multi-client product candidate if the Owner chooses that workflow and accepts its history limits. That is a **different** product decision from passing P0 unchanged.

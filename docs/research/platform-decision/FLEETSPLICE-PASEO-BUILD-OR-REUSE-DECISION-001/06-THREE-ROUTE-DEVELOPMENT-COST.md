# R06 — lifetime burden and system boundary

These are **relative ranges**, not fabricated engineer-hours or measured resource budgets. Assumptions: one Owner, at least a Windows ZenBook and later heterogeneous Host, existing local Codex credentials, optional self-hosted remote path, unchanged P0 semantics, and a many-day history with large tool outputs. “Already written” FS code lowers incremental work only where it passes the same requirement; it is not a reason to fund future work.

No route gains a cost advantage from comparing a small bounded FS projection against Paseo's larger ADE feature set. Compare the required *control* loop and complete history at equivalent correctness, then total process tree, installation and support. Paseo's broad editor/worktree/terminal features may be valuable to some users; they do not establish necessity to duplicate them in FS. The [Owner thesis](../../../product/owner-thesis.md) explicitly keeps native tools and Windows Terminal authoritative.

## CL, JIF and model placement

CL retains Goal-first admission, evidence references and final route/Owner decision; a Paseo Agent ID or FS LogicalSession is an execution/evidence pointer, not second Goal ownership. An eventual connector must exchange stable native/Host/Workspace/effect receipts and uncertainty statuses, with no automatic replay. None is implemented by this study.

JIF owns machine/service deployment and inventory. Neither FS nor Paseo gains authority over a GPU Host merely because Codex runs on a laptop. A native Codex model-provider configuration may point to an Ollama/vLLM/LiteLLM OpenAI-compatible endpoint on another Host; first qualify native network, auth and model behavior. [Ollama's Codex integration](https://github.com/ollama/ollama/blob/8e4dad49f9f527762610fd419ee2ae39207f67a4/docs/integrations/codex.mdx) illustrates the native provider path. A new FS model gateway is not justified by this placement alone.

An independent FS Hub is justified only if the Owner needs cross-Host controller authority, durable effect/audit reconciliation and self-hosted outbound remote continuity that an existing multi-Host Paseo deployment cannot provide at lower lifetime burden **and** the native shared endpoint exists for the actual Host mode. Multi-Host inventory alone is not enough; Paseo already routes clients to several daemons. The current recommendation therefore waits at the native availability gate before admitting further FS G08 implementation.

## Alternative ownership arrangements considered

| Candidate | Process/session facts | Useful property | Rejected or retained as |
| --- | --- | --- | --- |
| HAPI Hub + Runner | Hub SQLite session/message/machine projection; local Runner and OS/native Agent hold process and thread facts | Central mobile directory with heterogeneous adapters | Retain directory and local representative; reject Hub row or volatile PID map as sole native truth |
| Orca rich runtime near Host | Local daemon/server owns projects, worktrees, PTY, accounts, Agent processes and UI/runtime state | Execution and credential locality; strong local ownership | Retain local authority; reject full rich server per Environment as default FS core |
| Full rich server per Environment | Each identity island repeats API, UI domain, accounts, history and update surface | Potentially direct local operation | Design candidate rejected for Fleet duplication/coordination burden; resource delta was NOT MEASURED |
| Hub supervises remote process | Central lifecycle sees remote process through transport | Simple one-place command model | Rejected: transport loss or Hub restart cannot establish OS/native termination |
| PTY-only canonical chat | ANSI stream is canonical Agent record | Broad terminal compatibility | Rejected: loses structured tool/approval/session semantics; PTY remains separate optional capability |
| FS middle design | Stateful, process-thin Hub owns Fleet identity, policy, logical session, intent and durable receipts; Host Edge/Environment companion owns local principal, Workspace, native process and attempt journal; native Agent owns native session/context | Explicit split of logical versus effect truth | Working candidate, not empirical optimum |

## FS response and measured costs

SOURCE_FACT: [authority model](../../../architecture/authority-model.md) requires Hub journal before dispatch, Edge durable attempt before effect, explicit incarnation/fence and AMBIGUOUS_EFFECT without blind replay. [Two-stream contract](../../../architecture/realtime-two-stream.md) lets common structured Agent deltas update live presentation, while control/safety events drive bounded authoritative reconciliation. It rejects screen scraping as effect authority. LogicalSession, SessionLane and NativeSegment keep native thread distinct from Fleet history. This is stronger vocabulary than a single session row, but only a tested fault result can prove stronger recovery.

MEASURED, limited to FS fixture: [Gate P](../../../performance/t03-perf-closeout-gate-p.md) changed discovery 74→18 total RPC with loaded=64/eligible=8, metadata read 56→0 and equal candidate set; submit/steer/interrupt pre-effect readThread 2→1, post-effect readThread remained 1. One common-turn snapshot was observed within a ≤2 bound. A 20-minute local soak found no unexplained memory growth. Three full-suite failures remained on an unqualified Codex managed pin. No HAPI/Orca/Paseo data share this fixture, so the result cannot rank products.

INFERENCE: the middle design may reduce repeated rich-runtime surfaces and prevent a central transport from claiming native process truth. Countercosts are Hub hops, Edge journals, identity reconciliation, deployment and compatibility complexity. No CPU/RAM ratio, global optimum or reliability superiority follows from the architecture diagram alone. Current HAPI/Orca implementation changes must be tested, not projected from the original issue list.

## Ambiguity classification and concrete gaps

For submit, steer, interrupt and approval, a lost response after dispatch is an effect-unknown state until exact native observation or an idempotent protocol proof resolves it. Retrying a request ID only helps if the effect owner durably remembers that ID. FS candidate states this rule; the other systems' *unverified* general behavior is UNKNOWN, not "unsafe." HAPI old [issue #929](https://github.com/tiann/hapi/issues/929) and Orca old [issue #11006](https://github.com/stablyai/orca/issues/11006) are historical failure samples, not current prevalence estimates. Paseo's documented [timeline repair](https://github.com/getpaseo/paseo/blob/b58af43a0675f2cd83d7b44489dd6cb58da79268/docs/timeline-sync.md) is a real counterexample to equating live-event loss with lost history.

The main implementation-versus-documentation gap is cross-product fault evidence: no common same-native-agent fault harness has been run. FS's specific remaining implementation/qualification gaps are Codex 0.162.1 same-thread Writer, live G06, byte-bounded durable G08 history and multi-Environment qualification. Paseo has a documented active Codex thread refusal case and an import pathway; whether it can safely control a concurrently active external writer remains U. An absent matching term such as "Fleet Controller" in HAPI/Orca/Paseo is a vocabulary difference until a scenario demonstrates a conflicting effect.

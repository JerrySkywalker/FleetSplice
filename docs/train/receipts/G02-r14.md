## Finding

### Medium

1. **Stage O does not bind result-specific evidence, so recovery can falsely
   commit a no-effect terminal result and tombstone R.** After
   `D=DELIVERY_EFFECT_POSSIBLE`, fencing the exact delivery owner/incarnation
   proves that it cannot emit in the future, but it does not establish whether
   that owner crossed the exact final native effect boundary before the fence.
   The current O rule accepts either the attempt owner's qualified native return
   or recovery proof that the owner is fenced and non-emitting, then allows the
   recovery writer to select absorbing `DELIVERY_EFFECT_POSSIBLE`,
   `ALREADY_TERMINAL`, `CANCELED_NO_EFFECT`, or `UNSUPPORTED`, or to select
   `AMBIGUOUS_EFFECT`, without a writer/result-specific evidence predicate for
   each row. A recovery writer possessing only no-future-emission proof can thus
   falsely commit a no-effect classification after an earlier emission; that O
   result becomes absorbing and atomically tombstones R, eliminating the only
   precommitted ambiguity-resolution path.

   The bounded correction must bind, into the transition-table digest, the
   exact eligible writer and qualified evidence predicate for each distinct O
   result row. A recovery writer with only owner-fencing/no-future-emission
   proof may select only `AMBIGUOUS_EFFECT`. Any nonambiguous O result requires
   qualified result-specific evidence proving whether the exact final native
   boundary crossed before the fence and supporting that exact result. This
   preserves R whenever the past emission fact is unresolved instead of
   allowing an unsupported absorbing result to tombstone it. References:
   `docs/architecture/baseline-0.1.md:1007-1019,1106-1177`;
   `docs/architecture/authority-model.md:108-170`;
   `docs/adr/0001-hub-edge-command-and-failure-boundary.md:414-515`;
   `docs/adr/0002-session-identity-control-and-authority.md:168-247`; and
   `docs/adr/0004-windows-runtime-storage-and-native-helper.md:305-393`.
